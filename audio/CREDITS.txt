乒乓球音效素材说明 / SFX credits
================================

audio/hit1~4.wav —— 真实对打录音里切出的击球声（2026-10-08 起在用）
==================================================================
★★ 当前在用。四条变体取自**同一段真实对打里的四个不同击球**，
   不是同一段改音高 —— 这是「连打十几拍听不出复读」的根本保证。

来源: B 站视频 BV1WQ4y1h7Ar「乒乓球 打球 运动 音效 (HQ)」
      https://www.bilibili.com/video/BV1WQ4y1h7Ar/   UP主 8号披萨PizzaNo8
      素材包里的 ref_bilibili_打球队列.wav = 该视频音轨裁掉首尾静音后的 5.60 s 片段
      （素材包位置: Desktop/scnuer/pingpong_sfx/，是用户交给本项目的）

⚠️⚠️ 授权：**不是 CC0 / 公共领域**。B 站视频版权默认归 UP 主所有。
      这条是**用户明确指定使用**的（2026-10-08，用户原话「用 3」）。
      公开发布的版本里包含这段音频 = 有版权风险。要商用请先联系 UP 主取得许可，
      或把 audio/hit1~4.wav 换成可自由分发的素材后重新导出 exe / zip。
      要换成 CC0：见下方「已停用」段里那批 BigSoundBank 素材（但那是**球落地弹跳**，
      不是球拍击球，音色差得远）。

提取方式（可复现，脚本随工程走）:  python tests/_make_hit_from_rally.py
  1) 谱通量起音检测 → 定位 19 次击球
  2) 挑信噪比最好的 4 下：0.16 / 0.89 / 1.69 / 4.12 s
  3) 起点做样本级对齐；2 阶 130 Hz 高通去低频轰鸣；首尾淡入淡出
  4) 自适应截断（峰值后跌 32 dB 处再留 22 ms），硬上限 175 ms
  5) 按「起音后 60 ms 的 RMS」等响化到 -23.93 dBFS
输出格式: 48 kHz / 16-bit / 单声道 PCM

实测（等响化之后）
  文件       源位置   时长     峰值        60ms-RMS    频谱重心   频带能量（<300 / 0.3-1k / 1-3k / 3-6k / >6k）
  hit1.wav    0.16 s   70 ms   -0.75 dBFS  -23.93 dB   6128 Hz    0.3 / 7.6 / 46.9 / 8.8 / 36.4 %
  hit2.wav    0.89 s  115 ms   -4.14 dBFS  -23.93 dB   3977 Hz    1.3 / 21.0 / 72.7 / 1.3 / 3.6 %
  hit3.wav    1.69 s   70 ms   -5.33 dBFS  -23.93 dB   2835 Hz    0.1 / 39.7 / 59.0 / 0.2 / 0.9 %
  hit4.wav    4.12 s   70 ms   -2.83 dBFS  -23.93 dB   4453 Hz    1.4 / 20.6 / 65.8 / 5.7 / 6.5 %
  ★ 频谱重心口径：对**成品文件整段**做 Hann 窗 FFT，取幅度谱的一阶矩
    （与本文档其余条目同口径）。四条跨度 2835~6128 Hz —— 差异来自**不同的击球**，
    不是同一段的音高变化，这正是「连打听不出复读」的依据。
  ★ hit1 明显更「亮」（>6k 占 36%），它也是四条里最响的一条；
    hit3 最闷（重心 2835 Hz）—— 混着用，音色有自然起伏。

★ 为什么要按 RMS 而不是峰值归一（踩过的坑）：
  70 ms 的脆击球和 115 ms 的钝击球，**峰值一样时响度能差 3 dB 以上**。
  四条按峰值对齐后峰值只差 4.6 dB，但听感是齐的 —— 因为对齐的是 RMS。
  反之若按峰值归一到同一个数，四条之间会出现明显的高低差。
  → 所以 pingpong_audio.gd 的 `hit_db` **一个数都没改**（仍是 -4.0）：
    -23.93 dBFS 正是被替换掉的合成 hit.wav 在同一口径下的数值。

★ 音高抖动仍保留：`play_hit()` 每拍 `randf_range(0.94, 1.06)`（±6%），
  叠在 4 条不同素材上，重复感比单条素材时更低。


audio/bounce.wav —— 程序合成的台面弹跳（**未改动**，仍在用）
==========================================================
★ 这次没换，理由：
  ① 那段对打素材里**只有球拍击球**，没有台面弹跳，切不出来；
  ② CC0 那批（BigSoundBank）录的是**球落在瓷砖地面**连续弹跳，
     和球台差得远 —— 2026-10-03 用它做过，用户反馈「不像」，就是这里。
合成参数（脚本 %TEMP%/cs1_tools/gen_audio.py，2026-10-02）
  输出格式: 22050 Hz / 16-bit / 单声道 PCM
实测: 时长 10.3 ms(-20dB) / 频谱重心 3933 Hz / 低中高能量占比 0.07 / 0.59 / 0.34
      → 明显偏中低频，和 hit 的「脆」形成对比，正是设计意图。
推子 `bounce_db = -9.0`（峰值 -2.5 dBFS），维持「击球比弹跳高 5 dB」。

audio/cheer1.wav、audio/cheer2.wav —— 真实观众呐喊（2026-10-03 新增）
----------------------------------------------------------------
来源: BigSoundBank (bigsoundbank.com) — 作者 Joseph SARDIN
授权: 同上，CC0 1.0 公共领域
原始母版 (44.1 kHz / 16-bit 立体声)：
  236  Shouts and Applauses of Teens #1
       https://bigsoundbank.com/detail-236-shouts-and-applauses-of-teens-1.html
  237  Shouts and Applauses of Teens #2
       https://bigsoundbank.com/detail-237-shouts-and-applauses-of-teens-2.html
生成方式（脚本 %TEMP%/cs1_tools/build_cheer.py）
  窗口 [起音-5ms, +2000ms]，线性插值重采样到 48 kHz，立体声混单声道
  淡入 0.3 ms / 淡出 80 ms，峰值归一到 -1.5 dBFS
输出格式: 48 kHz / 16-bit / 单声道 PCM

★ 为什么不用 0019「Applause: 150 People」/ 0021「Applause: 600 People」
  实测这两条的起音在 303 / 712 ms、能量要 20 秒才堆起来（-26 dB → -15 dB），
  做得分反馈会明显「迟到」，而且整段里没有一个可以剪出来的瞬时爆发点。
  0236 的起音只有 11 ms、905 ms 到峰值、之后 1.7 s 内衰减到 -25 dB ——
  形状正好是「一记呐喊」，这是选它的唯一理由。


其余音效仍是程序化合成的 16-bit PCM WAV
  net.wav / whoosh.wav / crowd.wav / hit_soft.wav / hit_spin.wav
  ★ hit_soft / hit_spin（下旋的闷「噗」、上旋的摩擦「沙」）**没有跟着换**：
    它们是刻意做出来与普通击球不同的两个音色，不是「同一个声音调个 pitch」。
    现在 HIT 是真录音、这两个是合成音，来源不同是**有意保留**的差异。

★ audio/nailong_laugh.mp3 是**失分挖苦音**，已从呐喊池里摘出（2026-10-03 用户定：
  「失分用奶龙笑，得分呐喊」）。下面是它当年被拿来当「呐喊」时的对照数据，
  仅作「人声带」参考 —— 它**不再**是 CHEER_VARIANTS 的一员，
  见 pingpong_audio.gd 的 play_concede()。

频段对照（功率谱能量占比，用来确认「是不是人声」）：
  文件                  <300   0.3-1k   1-3k   3-6k   >6k     重心
  cheer1.wav            0.1%   68.8%   24.6%   5.5%   1.0%   1310 Hz
  cheer2.wav            0.3%   36.0%   48.5%  12.9%   2.4%   1808 Hz
  nailong_laugh.mp3     1.2%   82.4%   14.7%   1.6%   0.0%    919 Hz
  crowd.wav（合成）     1.9%    7.0%   35.3%  36.5%  19.2%   3852 Hz
  → cheer1/2 与奶龙同落在人声带（0.3~3 kHz）；合成 crowd 是高频噪声，
    这就是它听起来像「沙沙声」而不是「有人在喊」的原因。
