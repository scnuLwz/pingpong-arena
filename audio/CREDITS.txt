乒乓球音效素材说明 / SFX credits
================================

audio/hit.wav、audio/bounce.wav —— 程序合成的球拍击球 / 台面弹跳
================================================================
★★ ★ 当前在用版本。这一对是**回退**来的：
   2026-10-02 定稿的合成版 → 2026-10-03 换成真实录音 → 2026-10-07 用户要求改回合成版。

合成参数（脚本 %TEMP%/cs1_tools/gen_audio.py，2026-10-02「击球音重做」）
  make_hit()  主体扫频 3000+240t ~ 9800-240t
              + 球壳共振 sin(2π·(4300+300t)·t)·exp(-130t)·0.26
              + 木拍共鸣 0.60（原 0.30）+ 闷响 0.18（原 0.10）
  输出格式: 22050 Hz / 16-bit / 单声道 PCM

实测指标（用来解释「为什么听起来和真实录音不一样」）
  文件                    -20dB 时长   频谱重心   低/中/高能量占比   峰值
  hit.wav（合成，在用）      12.8 ms      3834 Hz   0.20 / 0.25 / 0.55  -3.5 dBFS
  bounce.wav（合成，在用）   10.3 ms      3933 Hz   0.07 / 0.59 / 0.34  -2.5 dBFS
  hit1.wav（真实录音，停用）  2.4 ms      3984 Hz   0.26 / 0.36 / 0.38  -2.0 dBFS
  → 合成版瞬态长 5 倍多，听感明显更「闷、钝」，不是同一个音色。

★★ 这两个文件是怎么找回来的（重要，别删那个页面）
  旧样本原本归档在 `%TEMP%/cs1_tools/attic_audio_synth/`（见 2026-10-03 日志），
  但整个 cs1_tools 目录后来被清掉了，**回收站里也没有**。
  唯一的存档是工作区根目录的 `sfx_preview.html` —— 2026-10-03 为了让用户 A/B 试听，
  把「旧·合成」两条以 base64 内联进了那个单文件页面。
  ★ 取回时的自证方式：同一页里的 4 条「新」素材解码后与工程内
    hit1~4 / bounce1~4 **逐字节相同** → 证明解码链路无损，取回的「旧」也可信。
  ★ 只留存了 hit / bounce 各 **1 条**；2026-10-02 版的 hit2 / hit3 两个变体没留下，
    所以 `HIT_VARIANTS` 现在只有 1 项（不重新合成、不编造）。
    重复感靠每拍的 pitch 抖动化解：击球 ±6%、弹跳 ±9%。

推子（pingpong_audio.gd）—— 按合成素材标定，即 2026-10-03 之前的原值
  hit_db    -4.5 → -4.0   （合成峰值 -3.5 dBFS；真实录音是 -2.0，那 1.5 dB 是为它补的）
  bounce_db -8.5 → -9.0   （合成峰值 -2.5 dBFS）
  → 恢复「击球比弹跳高 5 dB」这个原有关系。

audio/cheer1.wav、audio/cheer2.wav —— 真实观众呐喊（2026-10-03 新增）
----------------------------------------------------------------
来源: BigSoundBank (bigsoundbank.com) — 作者 Joseph SARDIN
授权: 同上，CC0 1.0 公共领域
原始母版 (44.1 kHz / 16-bit 立体声)：
  236  Shouts and Applauses of Teens #1
       https://bigsoundbank.com/detail-236-shouts-and-applauses-of-teens-1.html
  237  Shouts and Applauses of Teens #2
       https://bigsoundbank.com/detail-237-shouts-and-applauses-of-teens-2.html
生成方式（脚本 %TEMP%/cs1_tools/build_cheer.py）
  窗口 [起音-5ms, +2000ms]，线性插值重采样到 48 kHz，立体声混单声道
  淡入 0.3 ms / 淡出 80 ms，峰值归一到 -1.5 dBFS
输出格式: 48 kHz / 16-bit / 单声道 PCM

★ 为什么不用 0019「Applause: 150 People」/ 0021「Applause: 600 People」
  实测这两条的起音在 303 / 712 ms、能量要 20 秒才堆起来（-26 dB → -15 dB），
  做得分反馈会明显「迟到」，而且整段里没有一个可以剪出来的瞬时爆发点。
  0236 的起音只有 11 ms、905 ms 到峰值、之后 1.7 s 内衰减到 -25 dB ——
  形状正好是「一记呐喊」，这是选它的唯一理由。

★ 为什么要新找一条真实呐喊，而不是继续只用奶龙
  ★ 这条历史说明的**结论已经变了**（2026-10-03 用户定稿）：奶龙不再是呐喊的一种，
    而是**失分挖苦音**。呐喊池现在只剩 cheer1 / cheer2 两条 —— 理由见上方。
  最初的做法是把奶龙当呐喊用，单局要响十几次，第三次就听得出是复读；
  连拍里程碑需要一个正经的现场欢呼。

频段对照（功率谱能量占比，用来确认「是不是人声」）：
  文件                  <300   0.3-1k   1-3k   3-6k   >6k     重心
  cheer1.wav            0.1%   68.8%   24.6%   5.5%   1.0%   1310 Hz
  cheer2.wav            0.3%   36.0%   48.5%  12.9%   2.4%   1808 Hz
  nailong_laugh.mp3     1.2%   82.4%   14.7%   1.6%   0.0%    919 Hz
  crowd.wav（旧合成）   1.9%    7.0%   35.3%  36.5%  19.2%   3852 Hz
  → cheer1/2 与奶龙同落在人声带（0.3~3 kHz）；旧的合成 crowd 是高频噪声，
    这就是它听起来像「沙沙声」而不是「有人在喊」的原因。

其余音效仍是程序化合成的 16-bit PCM WAV（net / whoosh / crowd + hit_soft / hit_spin）。

★ audio/nailong_laugh.mp3 现在是**失分挖苦音**，已从呐喊池里摘出（2026-10-03 用户定：
  「失分用奶龙笑，得分呐喊」）。上面那张频段表里它的数据仅作人声带对照参考，
  它**不再**是 CHEER_VARIANTS 的一员 —— 见 pingpong_audio.gd 的 play_concede()。
